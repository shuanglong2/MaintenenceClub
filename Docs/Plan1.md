# 维修组内部服务器: 开发计划 (Plan1)

## 1. 目标与边界

为学校维修组 (1 组长, 4 副组长, 1 财务, 30 组员) 做一个只在内网使用的网页系统, 管理人员, 任务, 活动日程, 日志与维修记录, 库存, 财务, 文档资料.

原则:

- 小而够用: 能跑起来, 能看懂, 一个人能维护
- 低资源: 固定在 J1800 / 2 GB 内存 / 32 GB 硬盘上运行, 不再更换机器
- 文档只用 Markdown, 方便人看, 也方便直接丢给 AI
- 不碰学校禁止的东西: 会费, 捐赠, 在线支付, 对外收款

明确不做:

- 会费, 捐赠, 在线支付
- 审批流, 复式记账, 税务, 应收应付
- Office 在线编辑 (Word, Excel, PPT)
- 多社团, 邮件系统, 原生手机 App (网页自适应手机即可)
- 对公网开放

## 2. 技术选型

| 项目 | 选择 | 说明 |
|---|---|---|
| 系统 | Ubuntu Server 26.04 LTS | 无桌面 |
| 语言 | Go | 标准库 `net/http` 与 `html/template`, 不引入前端编译, 不用 Node |
| 数据库 | PostgreSQL 18 | 与应用一起跑在这台机器上 |
| Web 服务 | Nginx 反向代理 | 应用只监听 `127.0.0.1` |
| Markdown | Goldmark | 禁用原始 HTML, 防 XSS. 做文档模块时再引入 |
| PDF | 首期不做 | 需要导出时再选纯 Go 库 |
| 认证 | Cookie 与 bcrypt | 不开放注册, 由组长建账号 |
| 部署 | 单个静态二进制 | `CGO_ENABLED=0`, `GOAMD64=v1`, systemd 管理, 不用 Docker |

约束:

- 编译固定 `GOAMD64=v1`, 以适配没有 AVX 的 J1800
- 依赖和 `go.sum` 只在 GitHub Actions 里生成, 下载产物后再提交
- 前端只用少量原生 JS 或 htmx, 放在 `Res`, 不依赖外网 CDN

## 3. 角色与权限

账号角色三选一, 外加一个 "财务" 开关:

| 功能 | 组长 | 副组长 | 组员 | 财务 (附加) |
|---|---|---|---|---|
| 账号与角色管理 | 全部 | 只读 | 仅自己的资料 | - |
| 任务 | 创建, 分配, 改全部 | 创建, 分配, 改全部 | 创建, 改自己负责或自己创建的 | - |
| 活动与日程 | 创建, 改 | 创建, 改 | 查看, 报名, 签到 | - |
| 日志与维修记录 | 写, 改全部 | 写, 改全部 | 写, 改自己的 | - |
| 库存 | 增删改, 盘点 | 增删改, 盘点 | 查看, 登记借还, 登记领用 | - |
| 财务 | 只读 | 只读 | 不可见 | 读写 |
| 文档 | 读写, 可设可见范围 | 读写, 可设可见范围 | 读写 (按可见范围) | - |
| 系统设置, 备份, 审计日志 | 全部 | 只读审计 | - | - |

文档页面可见范围只有两档: 全员 / 仅管理层 (组长 + 副组长).

## 4. 架构

一个网站进程, 内部按模块分目录.

```
Src/cmd/mclub/           程序入口
Src/internal/
  people/
  tasks/
  events/
  logs/
  inventory/
  finance/
  docs/
  shared/                认证, 授权, 布局, 审计, 文件存储, 备份
```

PostgreSQL 使用规则:

- 一个数据库, 每个模块一个 schema
- 其他模块保存 `PersonId`, 并在需要时冗余保存当时的姓名. 人员退出只改状态, 不删除记录
- 金额一律用整数 (单位: 分)
- 时间统一存 UTC, 页面按 UTC+8 显示
- 数量类数据存流水, 结余用加总得到, 不单独存可被改乱的余额

文件存储:

- 文件放在磁盘目录 `uploads/<模块>/<年>/<月>/<随机名>`, 数据库只记路径, 原文件名, 大小, 类型, 上传人
- 校验扩展名与大小, 重命名为随机名, 防路径穿越; 下载走授权后的接口, 不由 Nginx 直接暴露

通用能力:

- 审计日志: 记录谁在什么时候改了什么 (账号, 角色, 财务, 库存, 文档删除等)
- 软删除: 财务, 库存, 文档不物理删除, 用 "作废" 并记录原因
- 全站搜索: 文档用 PostgreSQL 全文搜索; 其他模块先用简单 `LIKE`

## 5. 模块需求

### 5.1 人员 (People)

- 字段: 姓名, 登录名, 角色, 财务开关, 学号 (可选), 联系方式 (可选), 加入时间, 状态 (在组 / 已退出), 备注
- 账号由组长创建, 初始密码由组长设置, 首次登录强制改密
- 组员可看全员姓名与职务; 联系方式仅管理层和本人可见
- 退出的人员保留历史记录, 不能登录

### 5.2 任务 (Tasks)

- 字段: 标题, 说明 (Markdown), 类型, 状态, 优先级, 负责人, 参与人, 截止日期, 关联活动, 关联器材
- 类型: 科普活动, 创新竞赛, 实验室保养, 电脑软硬件维护, 其他
- 状态: 待办, 进行中, 完成, 取消
- 评论 (Markdown)
- 视图: 列表 (筛选: 我的 / 类型 / 状态), 看板按状态分列
- 首页展示 "我的未完成任务" 与 "即将到期"

### 5.3 活动与日程 (Events)

- 字段: 标题, 类型 (科普, 竞赛, 例会, 保养日, 其他), 开始和结束时间, 地点, 说明, 负责人
- 参加: 报名, 签到 (由负责人或管理层代为勾选即可), 参加记录
- 活动总结 (Markdown) 与附件 (图片, PDF)
- 视图: 月历, 列表; 首页展示近期活动
- 可由活动一键创建关联任务

### 5.4 日志与维修记录 (Logs)

- 日志类型: 工作日志, 维修记录, 保养记录
- 字段: 日期, 作者, 类型, 内容 (Markdown), 用时 (分钟, 可选), 附图
- 维修与保养记录额外字段: 对象 (器材 / 电脑 / 其他, 可关联库存里的器材), 现象, 处理, 结果, 更换的元件 (可选, 自动生成库存领用记录)
- 器材详情页能看到该器材的全部维修保养历史
- 报修单 (外部同学或老师送修电脑): 登记来源, 联系方式, 问题, 状态 (受理, 处理中, 待取, 完成). 首期做成维修记录的一种状态, 不单独做大流程

### 5.5 库存 (Inventory)

- 物品类别: 器材, 消耗品, 工具, 元件
- 物品字段: 编号, 名称, 类别, 规格, 单位, 存放位置, 最低库存 (消耗品, 元件), 照片, 备注
- 器材状态: 可用, 借出, 维修中, 报废; 借还需要记录人与时间
- 数量变动流水: 入库, 领用, 盘点调整, 报废; 当前数量 = 流水加总
- 低库存提醒显示在首页
- 位置用简单的树 (实验室 / 柜子 / 抽屉), 不做复杂仓库模型
- 后期可做二维码标签, 用手机扫码打开物品页

### 5.6 财务 (Finance)

只做单笔流水, 不做审批, 不做复式记账.

- 记录类型四种: 收入, 支出, 存入储蓄, 从储蓄取出
- 字段: 日期, 类型, 金额 (分), 分类, 备注, 经手人, 附件 (发票 PDF 或照片, 可多个)
- 分类可配置, 例如: 学校拨款, 活动经费, 器材, 耗材, 报销, 其他
- 报销就是一条支出, 分类选 "报销", 附上发票 PDF 和备注
- 期初余额用一条分类为 "期初" 的收入表示
- 余额由加总得到:
  - 手头 = 收入 - 支出 - 存入储蓄 + 从储蓄取出
  - 储蓄 = 存入储蓄 - 从储蓄取出
- 记错用 "作废" 并填原因, 原记录保留; 更正则新增一条
- 统计: 按月, 按分类汇总; 导出 CSV
- 权限: 财务读写, 组长和副组长只读, 组员不可见
- 发票原件原样保存, 系统不负责生成对外单据

### 5.7 文档 (Docs)

- 只支持 Markdown 页面与图片; 其他文件只能作为附件下载, 不在线渲染
- 目录树 (文件夹) 加标签, 页面可见范围: 全员 / 仅管理层
- 编辑: 文本框加实时预览, 图片拖入上传后自动插入 Markdown 引用
- 多人协作: 用版本号做乐观并发, 保存时若他人已改, 提示冲突并让用户选择覆盖或合并; 不做实时同时编辑
- 历史版本: 每次保存留一份, 可查看和还原
- 搜索: PostgreSQL 全文搜索 (中文先按字符分词, 效果不够再换方案)
- 对 AI 友好: 每页提供 `.md` 原文地址; 管理员可一键导出全部文档为 zip (目录结构 + md + 图片)

### 5.8 首页与通用

- 首页: 我的任务, 近期活动, 低库存, 最近文档修改, 财务摘要 (仅有权限者)
- 全站响应式布局, 手机能用
- 全站中文界面

## 6. 非功能需求

- 资源: 应用进程常驻内存目标小于 150 MB; 系统加 Nginx 加应用总占用小于 1 GB; 配置 1 GB 到 2 GB 交换分区
- 并发: 同时在线 10 人以内为设计目标, 峰值写入串行化即可
- 安全 (仅内网):
  - Cookie 认证, 防跨站请求伪造, 登录限速
  - Markdown 禁用 HTML 并输出前清洗
  - 上传限制大小与类型, 文件名随机化
  - 数据库文件与上传目录不在 Web 根目录, 目录权限仅服务用户可访问
  - 局域网内是否启用 HTTPS 见 "待确认"
- 备份:
  - 每天用 `pg_dump` 备份数据库, 保留最近 7 份
  - 上传目录增量同步到备份目录
  - 只有一块 32 GB 盘, 备份和上传都要限制体积
  - 恢复流程写进 README 并至少演练一次
- 可维护性: 每个模块目录结构一致, 命名一致, 便于让 AI 逐模块开发和修改; 业务规则 (余额计算, 数量流水) 写单元测试

## 7. 部署

目录约定:

```
/srv/maintclub/
  app/        当前发布目录 (符号链接指向 releases/<版本>)
  releases/   最近几个发布版本, 用于回滚
  uploads/    上传文件
  backups/    备份
```

PostgreSQL 的数据目录放在系统默认位置, 不放进网站目录.

- 服务以专用用户运行, systemd 配置自动重启
- Nginx 负责反向代理与上传大小限制 (如 `client_max_body_size 20m`); 内网访问用固定 IP 或内网域名
- 发布流程: 在 GitHub Actions 里构建并生成发布包 → 服务器下载 `linux-x64` 二进制到新目录 → 切换符号链接 → 重启服务; 出问题时切回上一版本
- 数据库迁移用 SQL 文件; 升级前先做一次备份
- 不在服务器上安装 Go, 不在服务器上编译; 不使用自托管 Runner
- 第一步先在 J1800 上跑一个 Hello 页面, 验证二进制, Nginx, PostgreSQL 和内存占用

## 8. 工程与 CI (全部在 GitHub Actions 云端)

- 仓库托管在 GitHub, 本机不安装也不使用编译环境, 提交中不把 Cursor 作为 contributor
- 流水线在推送时运行. 若一次提交只改动 `Docs`, 则跳过编译
  1. 缓存 Go 模块和构建结果, 成功后删除过期缓存
  2. `gofmt` 检查格式并输出差异
  3. `go mod tidy`. 若 `go.mod` 或 `go.sum` 有变化, 上传产物并失败, 下载后再提交
  4. `go test`
  5. 交叉编译 linux-x64 与 win-x64, `CGO_ENABLED=0`, `GOAMD64=v1`. Linux 去掉调试信息并保持全优化, 两个平台再用 UPX LZMA 压缩, 写入 `Publish`
  6. 上传 `Publish` 为 artifact
- 根目录说明只保留 `README.md` 和 `CHANGELOG.md`. 计划与技术文档放 `Docs`

## 10. 机器

长期只用 J1800 / 2 GB 内存 / 32 GB 硬盘.

- 编译目标保持 `GOAMD64=v1`
- PostgreSQL 收紧内存: `shared_buffers` 约 128 MB, `max_connections` 约 20, 关闭 `jit`
- 交换分区约 1 GB
- 上传和备份限制体积, 避免占满磁盘
